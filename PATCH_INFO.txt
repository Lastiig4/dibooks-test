DiBooks Patch - Instant Auth
===========================

WAAROM LOGIN EN LOGOUT TRAAG WAREN

Login:
1. Supabase signInWithPassword
2. profiles UPSERT
3. profiles SELECT
4. onAuthStateChange kon dezelfde profile-flow nogmaals starten
5. AuthModal wachtte op al die stappen voordat hij sloot

Logout:
- De UI wachtte op de Supabase signOut netwerk-call.
- De eerdere defensieve logout-fix kon daarna ook nog een extra session-check doen.

Extra:
- createSupabaseBrowserClient() maakte bij iedere aanroep opnieuw een browserclient.

WAT DEZE PATCH VERANDERT

- Eén gedeelde Supabase browserclient voor de hele app.
- Login wacht alleen nog op de echte wachtwoord-login.
- Zodra Supabase de login bevestigt, is de UI direct ingelogd.
- Profile role/plan wordt daarna op de achtergrond geladen.
- Dubbele gelijktijdige profile refreshes voor dezelfde user worden samengevoegd.
- Logout zet de DiBooks UI/cache direct op guest.
- Supabase signOut loopt daarna zonder de UI te blokkeren.
- Een trage oude profile request kan na logout de gebruiker niet opnieuw zichtbaar maken.
- Admin -> Boekmoderatie blijft behouden in AppNav.

INSTALLEREN

1. Pak de ZIP uit.
2. Sleep 'lib' en 'components' over dibooks_author_studio.
3. Kies Bestanden vervangen.
4. Geen SQL nodig.
5. Test lokaal:
   npm run build
6. Daarna commit/push.

TEST

- Klik Login en log in.
  De modal hoort vrijwel direct na de Supabase login-response te verdwijnen.
- Klik Uitloggen.
  De navbar hoort onmiddellijk naar Login / Registreer te wisselen.

LET OP

De daadwerkelijke Supabase wachtwoordcontrole blijft natuurlijk een netwerk-call.
Dus 0 milliseconden login kan niet, maar de extra profile roundtrips blokkeren
de interface niet meer.

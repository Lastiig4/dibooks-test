DiBooks Instant Auth V4 - No getSession race
=============================================

Deze patch is gebaseerd op de auth.ts die je zelf zojuist hebt gestuurd.

Belangrijkste fix:
- bootAuthOnce doet NIET langer getSession() en onAuthStateChange tegelijk.
- Supabase onAuthStateChange levert zelf INITIAL_SESSION.
- In de auth callback worden alleen lokale React/DiBooks states aangepast.
- Profile queries starten pas NA de callback.
- TOKEN_REFRESHED veroorzaakt geen onnodige profile upsert/select.
- loginWithCredentials start niet langer zelf óók een profile refresh.
- registerWithCredentials idem.

Waarom:
Supabase gebruikt navigator Web Locks rond auth-operaties. Er zijn bekende
deadlock/race-problemen wanneer auth-initialisatie/getSession en listeners
tegelijk lopen. Het symptoom kan zijn dat signInWithPassword tientallen
seconden wacht.

Installeren:
1. ZIP uitpakken.
2. Sleep map 'lib' over dibooks_author_studio.
3. Bestanden vervangen.
4. Geen SQL nodig.
5. npm run build
6. Commit/push.

Test:
- Sluit voor de eerste test liefst andere DiBooks-tabs.
- Refresh de site.
- Log uit.
- Log opnieuw in.

De bestaande consolemeting blijft aanwezig:
[DiBooks Auth] Supabase signInWithPassword duurde XXXXX ms.

Als V4 nog steeds ~60 seconden geeft EN die consolemelding zelf ~60000 ms
aangeeft, dan zit de vertraging daadwerkelijk binnen de Supabase auth-call /
browser Web Lock en gaan we als volgende stap de client-lock zelf aanpakken.
